Projet de Fin d'Études — ENSA Oujda

Lakehouse Cloud Native — Marché de l'emploi Tech

Problématique

Le marché de l'emploi tech est dispersé entre de nombreuses plateformes , rendant difficile une vision consolidée des compétences réellement demandées. Ce projet propose un pipeline data engineering complet, open-source et portable vers le cloud (Databricks-ready), pour centraliser, nettoyer et analyser ces offres.

Architecture globale (Medallion)
  • Bronze — ingestion brute multi-sources vers MinIO (S3-compatible), écriture directe Python via boto3
  • Silver — nettoyage, déduplication et extraction des compétences techniques (dictionnaire + LLM)
  • Gold — agrégations métier via dbt pour l'exposition aux dashboards et agents IA
Sources de données
  • France Travail — API officielle (OAuth2)
  • Adzuna — API officielle
  • Rekrute.com — scraping HTML statique (BeautifulSoup)
  • Indeed (Maroc/France) — via un acteur Apify
Stack technique
  • Orchestration — Apache Airflow 3.2.2
  • Traitement — Apache Spark 3.5.1 (cluster standalone Docker), Delta Lake pour le versionnement des données
  • Stockage — MinIO (substitut local S3-compatible)
  • Transformation — dbt (Silver → Gold)
  • IA — Groq API (llama-3.3-70b-versatile) pour le filtrage de pertinence des offres
État d'avancement

Couche Bronze finalisée (4 sources intégrées). Couche Silver en cours de développement (déduplication et extraction des compétences). Prochaines étapes : transformations Gold via dbt, module d'agents IA, dashboards et déploiement Kubernetes possible.

Détection de Défauts Textiles

Problématique

L'inspection manuelle des tissus en industrie textile est lente, subjective et sujette à la fatigue humaine. Ce projet propose une alternative automatisée, fiable et déployable sur matériel standard.

Architecture globale
  • Vision — capture d'image par caméra, traitement par le modèle IA
  • Hardware — Arduino Uno pilotant une LED verte (OK) ou rouge (KO) via communication série
  • Cloud — dashboard ThingsBoard affichant le score d'anomalie en temps réel
Dataset — TILDA
  • 770 images normales — entraînement (75%)
  • 132 images défectueuses — validation (13%)
  • 130 images mixtes — test (12%)
Modèles évalués
  • EfficientAD (baseline) — Knowledge distillation teacher-student, très rapide, utilisé comme référence.
  • PatchCore (modèle final) — ResNet18 (couches 2+3), memory bank de patches normaux.
Résultats

PatchCore multicouches offre le meilleur compromis détection/faux positifs, avec localisation précise des défauts par heatmap.

🌤️ Pipeline Météo Temps Réel

Objectif

Construire un pipeline de streaming météorologique end-to-end, capable d'ingérer des données météo en temps réel depuis l'API Open-Meteo, de les traiter et normaliser via ksqlDB.

Architecture du pipeline
  • api_connectors — Connecteurs Python vers l'API Open-Meteo
  • producers — Producer Kafka publiant les données météo dans un topic en temps réel
  • normalizers — Normalisation et transformation des événements météo
  • docker/kafka-kraft — Cluster Kafka en mode KRaft (sans Zookeeper) conteneurisé
Points techniques notables
  • Utilisation de Kafka en mode KRaft — architecture moderne sans dépendance Zookeeper
  • Traitement et agrégation des features météo directement en streaming via ksqlDB
  • Déploiement entièrement conteneurisé via Docker Compose

  • Création de cohortes avec filtres dynamiques multicritères
  • Définition de règles de validation métier personnalisées
